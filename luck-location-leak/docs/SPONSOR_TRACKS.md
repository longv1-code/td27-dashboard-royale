# Sponsor tracks we are entering

| Track | What it does in the project | Code | Your setup step |
|---|---|---|---|
| **Best Use of Gemini API** | Four jobs. (1) "Ask the Pit Boss": grounded, multi-turn answers from the claims table, the machine's tests and retrieved floor notes, returned as schema-enforced JSON `{answer, cites, machines, follow_ups, confidence}`; the server drops any citation or machine id the page can't trace, and the UI turns them into "Show C3" / "Note N-…" / "Inspect M-1158" buttons and follow-up chips. (2) "Draft with Gemini" writes an inspection work order `{title, priority, checks, note}` from a machine's test results; a person edits and saves it. (3) `gemini-embedding-001` (768-d) embeds every floor note and every question for retrieval. (4) Per-IP rate limit so the public key can't be drained. | `server/app.py` → `/api/ask`, `/api/notes/draft`, `embed()` | Create a key at aistudio.google.com and put it in `.env` as `GEMINI_API_KEY`. |
| **Best Use of MongoDB Atlas** | The floor's memory. `notes` stores technician notes with their Gemini embeddings and is searched with **Atlas Vector Search** (`$vectorSearch` on index `notes_vec`, created by the server on first use, with `machine_id`/`status` filters) so the Pit Boss can cite what people found on the floor. `pitboss_log` is an audit trail of every AI answer (citations, confidence, notes used, latency, token usage) plus managers' helpful/not-helpful votes. `plans` stores locked $100k plans keyed by SHA-256. One `$facet` aggregation powers the live **Decision log** panel on the Evidence tab. | `server/app.py`, `integrations/mongodb/README.md` | Create a free M0 cluster and a database user, allow network access, and put the `mongodb+srv://…` string in `.env` as `MONGODB_URI`. Restart; the vector index takes about a minute to build. |
| **Best Use of Tiger Data** | `machine_hour` (1.3M rows) as a TimescaleDB hypertable with compression, a continuous aggregate behind `/api/hourly`, and `payout_fingerprint()`: one SQL call that flags M-1158 from its first day of data. | `integrations/timescale/schema.sql`, `load.py` | Create a Tiger Cloud service, put its connection string in `.env` as `TIMESCALE_URL`, then run `python integrations/timescale/load.py --data <release>/data` (creates the schema too; no psql needed). |
| **Best Use of Vultr** | Hosts the public dashboard and the API, which keeps the Gemini key off the browser, behind HTTPS. | `deploy/Dockerfile`, `deploy/VULTR.md` | Create an Ubuntu instance and follow `VULTR.md`. Pass the same `.env` to `docker run --env-file .env`. |
| **Best Domain Name from GoDaddy Registry** | The public URL judges open. | `deploy/VULTR.md` (Caddy config) | Register the domain and add an A record pointing at the Vultr IP. |
| **DEV Writing Challenge** | "Hold tells you in six months. Hit rate tells you on day one." | `docs/DEV_POST.md` | Publish it on dev.to with the hackathon tag and link it on Devpost. |
